# Security Policy

## Supported Versions

We actively support and provide security updates for the latest major version on the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| main    | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The TechBlog team takes the security of our software, readers, and user accounts seriously. If you believe you have found a security vulnerability in this project, please follow these steps:

1. **Do not disclose the issue publicly.** Please refrain from opening a public GitHub issue or publishing details before a fix is released.
2. **Submit a Private Vulnerability Report:**
   * Preferred: Use the [GitHub Security Advisory](https://github.com/dhruvpatel16120/blog-website/security/advisories/new) feature to privately disclose the issue.
   * Alternative: Email our security contacts directly at [security@techblog.com](mailto:security@techblog.com) or [eservice.dhruvpatel@gmail.com](mailto:eservice.dhruvpatel@gmail.com).

### Information to Include in Your Report

To help us triage and resolve the issue quickly, please include:
* A description of the vulnerability and its potential impact.
* Step-by-step instructions to reproduce the issue (proof-of-concept code, HTTP requests, or screenshots).
* Affected components or routes (e.g. API endpoints, authentication flows, database queries).
* Any suggested remediations or mitigations.

### Response & Disclosure Process

* **Acknowledgement**: We aim to acknowledge receipt of your report within **24–48 hours**.
* **Investigation & Assessment**: We will assess the severity and work on a patch in a private branch.
* **Resolution**: Once verified, we will merge the patch, publish a release notice, and credit you for the responsible disclosure (unless you prefer anonymity).
